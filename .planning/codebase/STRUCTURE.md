# Codebase Structure

**Analysis Date:** 2026-06-09

## Directory Layout

```
screenshot-artifact/
├── .github/
│   └── workflows/
│       ├── ci.yml          # CI gate: dependency shape, typecheck, pack, kind-gates
│       └── release.yml     # Release pipeline
├── skills/
│   └── screenshot-matcher/

├── src/
│   └── index.ts            # SemanticArtifactManifest export (sole TypeScript source)
├── .npmrc                  # npm/pnpm registry configuration
├── LICENSE                 # Apache-2.0
├── README.md               # Extension documentation
├── package.json            # Package metadata + cinatra artifact config block
└── tsconfig.json           # Standalone TypeScript config (targets src/, outputs dist/)
```

## Directory Purposes

**`src/`:**
- Purpose: TypeScript source for the artifact manifest
- Contains: Single file `index.ts` exporting `screenshotArtifactManifest`
- Key files: `src/index.ts`

**`skills/`:**
- Purpose: Cinatra skill definitions — LLM prompt files consumed by the platform's skill runner
- Contains: One subdirectory per skill, each containing a `SKILL.md`
- Key files: `skills/screenshot-matcher/SKILL.md`

**`.github/workflows/`:**
- Purpose: CI/CD automation
- Contains: `ci.yml` (build + kind-gates), `release.yml` (release automation)
- Key files: `.github/workflows/ci.yml`

## Key File Locations

**Entry Points:**
- `src/index.ts`: TypeScript manifest export — primary package entry point (`"main"` and `"types"` both point here)

**Configuration:**
- `package.json`: Package identity, peer dependencies, and `cinatra` block (machine-readable artifact config)
- `tsconfig.json`: TypeScript compiler options — `strict: true`, `target: ES2023`, `module: ESNext`, outputs to `dist/`
- `.npmrc`: Registry/auth configuration for pnpm

**Skill Definitions:**
- `skills/screenshot-matcher/SKILL.md`: Classification prompt, confidence bands, and JSON output contract for the screenshot matcher

**CI:**
- `.github/workflows/ci.yml`: Source-mirror-aware CI — skips standalone install/typecheck/test when `@cinatra-ai/*` peers are present

## Naming Conventions

**Files:**
- TypeScript sources: camelCase (`index.ts`)
- Skill directories: kebab-case matching the skill name (`screenshot-matcher/`)
- Skill definition files: uppercase `SKILL.md`
- Workflow files: lowercase kebab-case (`ci.yml`, `release.yml`)

**Directories:**
- Skill subdirectories: kebab-case matching the skill ID used in the manifest (`screenshot-matcher`)
- Source directory: `src/` (standard)

**Exports:**
- Manifest constant: camelCase with `Manifest` suffix (`screenshotArtifactManifest`)

## Where to Add New Code

**New accepted MIME type:**
- Update `accepts.file.mimeTypes` in `src/index.ts`
- Mirror the change in `package.json` under `cinatra.artifact.accepts.file.mimeTypes`

**New matcher skill:**
- Create `skills/<skill-name>/SKILL.md` with YAML frontmatter (`name`, `description`) and prompt body
- Add the skill reference `@cinatra-ai/screenshot-artifact:<skill-name>` to `skills.matchers` in `src/index.ts` and in `package.json`'s `cinatra.artifact.skills.matchers`

**Additional TypeScript utilities (if needed):**
- Add files under `src/` — they will be included by `tsconfig.json`'s `include: ["src/**/*.ts"]`

**Tests (if added):**
- Place alongside source or in a `tests/` or `__tests__/` directory at the repo root
- CI runs `pnpm test --if-present` for standalone repos

## Special Directories

**`dist/`:**
- Purpose: TypeScript compiler output (`tsc` target)
- Generated: Yes
- Committed: No (not present; generated by build)

**`.planning/`:**
- Purpose: GSD planning and codebase analysis documents
- Generated: Yes (by GSD tooling)
- Committed: Per project convention
